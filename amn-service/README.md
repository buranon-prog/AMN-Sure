# AMN Service — ระบบงานบริการ (แผนก Services)

ระบบแยกเฉพาะของ AMN สำหรับแผนก Services (ไม่ใช้ข้อมูลหรือบัญชีร่วมกับ ERP ในโฟลเดอร์หลักของ repo นี้)

- **แอดมิน** ลงงาน: ลูกค้า / เครื่อง / เข้าที่ไหน / กี่โมง
- **หัวหน้าช่าง** (เช่น พี่เหน่ง พี่โด่ง) จ่ายงานให้ช่าง — ระบบเรียงช่างตามความถนัดกับรุ่นเครื่องให้
- **ช่าง** เข้าสู่ระบบด้วยรหัสพนักงาน + รหัสผ่านของตัวเองบนมือถือ เห็นเฉพาะงานของตัวเอง → นำทาง → เช็คอิน (GPS) →
  เขียนสรุปงาน: **ยังไม่เสร็จ = Hold** (อัปเดตทุกครั้งที่เข้า) หรือ **เสร็จแล้ว = ส่งงาน**
- **แจ้งเตือน** เข้ามือถือทันทีเมื่อได้รับงาน / เลื่อนนัด / ยกเลิก และแจ้งออฟฟิศเมื่อช่าง Hold หรือส่งงาน
- **ติดตามตำแหน่งช่างแบบ Realtime** เฉพาะเวลางาน — หมุดบนแผนที่ออฟฟิศขยับเองภายในไม่กี่วินาที (LIVE, ความเร็ว,
  ทิศทาง, แบตเตอรี่) กดดูเส้นทางรายคนรายวันได้ และส่งตำแหน่งได้แม้ช่างล็อกจอ/ใช้ Google Maps (ผ่านแอปติดตามเบื้องหลัง)
- **Dashboard** สรุปงานรายคน รายเดือน, ประวัติการซ่อมของเครื่องและของพนักงาน, Export ข้อมูลทุกตารางเป็น CSV

## สิทธิ์การเข้าถึง (ต่างกันตามบทบาท)

| สิทธิ์ | ผู้จัดการ | หัวหน้าช่าง | แอดมิน | ช่าง |
|---|:-:|:-:|:-:|:-:|
| ดู Dashboard / งานทั้งหมด / ข้อมูลลูกค้า | ✓ | ✓ | ✓ | — |
| ลงงาน แก้ไข เลื่อนนัด ยกเลิกงาน | ✓ | ✓ | ✓ | — |
| จ่ายงานให้ช่าง (ตามความถนัด) | ✓ | ✓ | — | — |
| เพิ่ม/แก้ไข ลูกค้า สถานที่ เครื่อง | ✓ | ✓ | ✓ | — |
| ตั้งค่าความถนัดของช่าง | ✓ | ✓ | — | — |
| ดูตำแหน่งช่าง (Tracking) | ✓ | ✓ | ✓ | — |
| Export ข้อมูลงาน/ลูกค้า | ✓ | ✓ | ✓ | — |
| Export ประวัติตำแหน่ง (ข้อมูลส่วนบุคคล) | ✓ | — | — | — |
| จัดการบัญชีพนักงาน / บทบาท / รีเซ็ตรหัสผ่าน | ✓ | — | — | — |
| รับงาน: เห็นงานของตัวเองบนมือถือ เช็คอิน สรุปงาน | — | ✓ | — | ✓ |

- ตรวจสิทธิ์ที่ฝั่ง server ทุกหน้า ทุกการบันทึก และทุก API (ไม่ใช่แค่ซ่อนปุ่ม) — กำหนดไว้ที่เดียวใน `src/lib/permissions.ts`
- ช่างเปิดได้เฉพาะงานที่ถูกจ่ายให้ตัวเอง งานของคนอื่นจะได้หน้า "ไม่พบ"
- เปลี่ยนบทบาท / ปิดบัญชี มีผลทันทีโดยไม่ต้องรอให้พนักงานออกจากระบบ (อ่านสิทธิ์จากฐานข้อมูลทุก request)
- ใส่รหัสผ่านผิด 5 ครั้ง บัญชีถูกล็อก 15 นาที (ผู้จัดการปลดล็อกได้)

## Flow ของงาน

```
แอดมินลงงาน ──► รอจ่ายงาน (NEW) ──[หัวหน้าช่างจ่ายงาน + แจ้งเตือนช่าง]──► จ่ายงานแล้ว (ASSIGNED)
                                                                                │ ช่างเช็คอิน (GPS)
                                                                                ▼
              ┌──────────────── เช็คอินครั้งถัดไป ◄──── Hold (ON_HOLD) ◄── กำลังทำ (IN_PROGRESS)
              │                                          ▲  สรุปงาน "ยังไม่เสร็จ"    │ สรุปงาน "เสร็จแล้ว"
              └──────────────────────────────────────────┘                          ▼
                                                                              เสร็จแล้ว (COMPLETED)
```

- การเข้าหน้างานแต่ละครั้งเก็บเป็น 1 รายงาน (เวลาเช็คอิน/ส่งรายงาน, พิกัด, ระยะห่างจากหน้างาน, สรุปงาน, อะไหล่, เหตุที่ Hold, นัดครั้งถัดไป)
  — รวมกันเป็น **ประวัติการซ่อมของเครื่อง** (`/machines/[id]`) และ **ประวัติการซ่อมของพนักงาน** (`/technicians/[id]`)
- เช็คอินไกลจากพิกัดหน้างานเกิน 500 ม. จะขึ้นเตือน ⚠️ ให้ออฟฟิศเห็น
- ทุกการเปลี่ยนแปลงของงานบันทึกไว้ใน "ประวัติการดำเนินการ" (audit log)

## การแจ้งเตือน

| เหตุการณ์ | ใครได้รับ |
|---|---|
| แอดมินลงงานใหม่ | หัวหน้าช่างทุกคน (รอจ่ายงาน) |
| จ่ายงาน | ช่างที่ได้รับงาน |
| เลื่อนนัด / ยกเลิก / เปิดงานใหม่ | ช่างในงานนั้น |
| ถอนช่างออกจากงาน | ช่างคนนั้น |
| ช่าง Hold | คนลงงาน + คนจ่ายงาน + หัวหน้าช่าง |
| ช่างส่งงาน | คนลงงาน + คนจ่ายงาน |

ทุกการแจ้งเตือนอยู่ที่ไอคอนกระดิ่งในแอป และส่งเป็น **Web Push** เข้ามือถือ (เด้งแม้ปิดแอปอยู่) เมื่อพนักงานกด
"เปิดการแจ้งเตือน" ครั้งแรก

- Android (Chrome): ใช้ได้ทันที
- iPhone: ต้อง iOS 16.4 ขึ้นไป และต้อง "เพิ่มไปยังหน้าจอโฮม" แล้วเปิดแอปจากไอคอนนั้น (ข้อจำกัดของ Apple)

## การติดตามตำแหน่งแบบ Realtime (เฉพาะเวลางาน)

**ฝั่งออฟฟิศ** (`/tracking`): แผนที่สด — ตำแหน่งใหม่ถูกส่งมาที่หน้าจอผ่าน Server-Sent Events ภายใน ~2 วินาทีหลังถึง server
หมุดเลื่อนไปตำแหน่งใหม่เองโดยไม่ต้องรีเฟรช, ป้าย **LIVE** = ได้ตำแหน่งภายใน 90 วินาที, แสดงความเร็ว ทิศทาง แบตเตอรี่
และสถานะ "อยู่หน้างาน JOB-…" / "กำลังเดินทาง" — กดชื่อช่างเพื่อดูเส้นทางของวันนั้นพร้อม "กล้องตามตัว"

**ฝั่งช่าง** มี 2 ช่องทาง ใช้คู่กันได้:

| ช่องทาง | ส่งเมื่อไร | ความถี่ |
|---|---|---|
| แอป AMN Service (เว็บ) | ตอนเปิดแอปอยู่บนจอ — เปิด **🚗 โหมดเดินทาง** เพื่อให้จอไม่ดับระหว่างขับรถ | เคลื่อนที่ ≥ 20 ม. ทุก ~8 วินาที, อยู่กับที่ทุก 60 วินาที |
| แอปติดตามเบื้องหลัง (OwnTracks / Traccar Client — ฟรี) | **แม้ล็อกจอหรือใช้ Google Maps นำทาง** | ตามที่ตั้งในแอป (แนะนำ 10–15 วินาที / โหมด Move) |

ตั้งค่าแอปติดตามเบื้องหลัง: ช่างเข้า **บัญชี → ตั้งค่าติดตามตำแหน่งแม้ปิดหน้าจอ** (`/m/tracker`) กด "สร้างรหัสเชื่อมต่อ"
แล้วคัดลอก URL / Device identifier ไปใส่ในแอปตามขั้นตอนบนหน้าจอ รหัสเป็นของแต่ละคน ใช้ได้แค่ส่งตำแหน่งของคนนั้น
(เก็บเฉพาะ hash) สร้างใหม่หรือยกเลิกได้ตลอด และผู้จัดการยกเลิกให้ได้จากหน้าพนักงาน

Endpoint ของแอปเบื้องหลังคือ `/api/track` รองรับ 3 รูปแบบ: OwnTracks HTTP (JSON `_type: "location"`), OsmAnd/Traccar
(query `id, lat, lon, timestamp, speed[knots], bearing, batt`) และ Traccar JSON (`device_id`, `location.coords`) —
ทดสอบด้วยข้อมูลจำลองของแต่ละรูปแบบแล้ว ควรทดลองกับมือถือจริง 1 เครื่องตอนติดตั้ง (ดู header `X-Tracking-Result`
ของ response หรือสถานะบนหน้า `/m/tracker`)

**ความเป็นส่วนตัว / PDPA**

- Server เก็บตำแหน่ง **เฉพาะ** ตอนที่ช่างกด "เริ่มงาน" แล้ว จนถึง "เลิกงาน" และอยู่ในช่วง `TRACKING_START`–`TRACKING_END`
  (ค่าเริ่มต้น 07:00–20:00) — จุดที่ส่งมานอกเวลานี้ (รวมจากแอปเบื้องหลัง) ถูกทิ้งทันทีไม่บันทึก
- ลืมกดเลิกงาน ระบบปิดกะให้อัตโนมัติ ไม่มีการติดตามข้ามคืน
- ลบประวัติตำแหน่งที่เก่ากว่า `LOCATION_RETENTION_DAYS` วันอัตโนมัติ (ค่าเริ่มต้น 90)
- ประวัติตำแหน่ง export ได้เฉพาะผู้จัดการ — ควรแจ้งพนักงานและได้รับความยินยอมก่อนใช้งานจริง

## เริ่มต้นใช้งาน (เครื่อง dev)

```bash
cd amn-service
npm install
cp .env.example .env
# แก้ AUTH_SECRET (openssl rand -base64 32) และใส่ VAPID keys: npx web-push generate-vapid-keys
npm run db:push
npm run db:seed
npm run dev
```

บัญชีตัวอย่างจาก seed (รหัสผ่านทุกบัญชี `ChangeMe123!` หรือกำหนดเองด้วย `SEED_PASSWORD`):

| รหัสพนักงาน | บทบาท |
|---|---|
| `MGR001` | ผู้จัดการ |
| `ADM001` | แอดมิน |
| `SUP001` (เหน่ง), `SUP002` (โด่ง) | หัวหน้าช่าง |
| `TEC001`–`TEC004` | ช่าง |

ข้อมูลลูกค้า/เครื่อง/งานใน seed เป็นข้อมูลสมมติสำหรับทดลองเท่านั้น สำหรับใช้งานจริงให้รัน
`SEED_DEMO=false SEED_PASSWORD='…' npm run db:seed` เพื่อสร้างเฉพาะบัญชีผู้จัดการ `MGR001` แล้วเพิ่มพนักงานจากหน้า
"พนักงาน & บัญชี"

## Deploy ใช้งานจริง

ช่างใช้งานจากมือถือนอกออฟฟิศ ระบบจึงต้องเข้าถึงได้ผ่านอินเทอร์เน็ต และ **ต้องเป็น HTTPS** (มือถือจะไม่ให้ GPS และ
Push Notification กับเว็บที่ไม่ใช่ HTTPS)

1. ใช้ PostgreSQL: แก้ `provider = "postgresql"` ใน `prisma/schema.prisma` และตั้ง `DATABASE_URL`
2. ตั้ง `AUTH_SECRET`, `AUTH_TRUST_HOST=true`, `WEB_PUSH_PUBLIC_KEY` / `WEB_PUSH_PRIVATE_KEY` / `WEB_PUSH_SUBJECT`
3. `npm run build && npx prisma db push && npm start` หลัง reverse proxy ที่มี HTTPS (เช่น Nginx/Caddy)
   หรือ deploy บนแพลตฟอร์มที่มี HTTPS ให้อยู่แล้ว
4. แผนที่สดใช้ Server-Sent Events: ถ้ามี Nginx ข้างหน้า ให้ปิด buffering สำหรับ `/api/tracking/stream`
   (`proxy_buffering off;` — แอปส่ง header `X-Accel-Buffering: no` ให้แล้ว)
5. แผนที่ใช้ tile ของ OpenStreetMap ซึ่งเหมาะกับการใช้งานปริมาณน้อย ถ้าใช้งานหนักให้เปลี่ยน URL tile ใน
   `src/components/LiveTracking.tsx` เป็นผู้ให้บริการแผนที่แบบเสียเงิน

## ทดสอบ

```bash
npm run typecheck
npm run build
# E2E (ต้องมี playwright + Chromium และรันกับฐานข้อมูล dev ที่ seed แล้ว):
BASE=http://localhost:3000 node tests/e2e.js
```

`tests/e2e.js` ตรวจทั้งเรื่องสิทธิ์ของแต่ละบทบาท (ช่างเข้าหน้าออฟฟิศไม่ได้, แอดมินจ่ายงานไม่ได้, ช่างเปิดงานคนอื่นไม่ได้,
เปลี่ยนบทบาท/ปิดบัญชีมีผลทันที) และ flow เต็ม: ลงงาน → แจ้งเตือนหัวหน้า → จ่ายงานตามความถนัด → แจ้งเตือนช่าง →
เริ่มงาน/แชร์ตำแหน่ง → เช็คอิน → Hold → เช็คอินใหม่ → ส่งงาน → แจ้งเตือนออฟฟิศ → เลิกงานแล้วไม่รับตำแหน่ง
และ realtime: ส่งจุดจาก OwnTracks / OsmAnd / Traccar JSON แล้วหมุดบนแผนที่ออฟฟิศขยับเองโดยไม่รีเฟรช, ขยับมือถือ
(แอปเว็บ) แล้วออฟฟิศเห็นภายในไม่กี่วินาที, token ผิด = 401, ไม่ได้เริ่มงาน = ไม่บันทึก
